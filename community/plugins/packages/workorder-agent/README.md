# workorder-agent

[简体中文](README.zh-CN.md)

Self-developed DeepSeek Harness bundle for NetEase design workorder operations:

- Queries 易协作 (GCP MCP) workorders that are 美术完成 within a date range.
- Checks required fields, persists issue snapshots, and refreshes by `updated_on`.
- Builds reviewable previews and sends aggregated POPO notifications.
- Mounts a standalone control plane under `/workorder-agent` with pages for
  overview, issues, webhook events, reviews, POPO message tracking, inspection,
  and settings.

This package declares `dsh.bundle` metadata and is installed from the tarball
generated by `packages/workorder-agent` in the community plugins workspace.

## Configuration

Configuration is frontend-first and requires no preset environment variables:

1. Open `/workorder-agent` on first boot and fill the admin token, webhook
   token, 易协作 GCP user key, POPO group robot URL and secret, data directory,
   and project ids in the bootstrap form.
2. Saving writes the values to the Harness `workorder-agent` settings namespace
   and reloads immediately; the same address then serves the control plane.

The `gcp` MCP connection used for agent-side semantic review is not created by
this form; add it in the plugin manager and set the `gcp-host` and
`gcp-user-key` request headers when needed.

Environment variables only act as first-boot fallbacks when present:
`ADMIN_TOKEN`, `WEBHOOK_TOKEN`, `GCP_USER_KEY`, `GCP_MCP_URL`, `GCP_HOST`,
`POPO_WEBHOOK_URL`, `POPO_WEBHOOK_SECRET`, `DATA_DIR`, and the project id
variables.

When `enabled` is false the host plugin does not mount the control plane; when
required tokens are missing it serves the bootstrap form and loads the control
plane once they are completed. Neither state takes down the web host.
