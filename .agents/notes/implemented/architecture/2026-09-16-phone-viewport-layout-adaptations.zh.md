# Agent Note: 手机视口布局适配

Status: implemented

[English](2026-09-16-phone-viewport-layout-adaptations.md) | 中文

## Problem

Web 客户端为窄窗口准备了断点，却没有面向手机宽度的布局方案，于是 390px 视口把桌面几何压进手机宽度里。在 390x844 下对运行中的 `dsh web` 实测：

- **框架。** 重新展开的侧边栏仍占据网格轨道。`computeColumns` 从不让侧边栏让步，于是 `center = max(0, viewport - sidebar)` 让 280px 的侧边栏旁边只剩 110px 中栏，而中栏的 `overflow: hidden` 把会话内容裁掉，既不滚动也不换行。
- **设置。** 弹窗保留 188px 导航栏与内容区并排。`max-width: calc(100vw - 48px)` 之后，内容区只剩约 155px，字段行把标签折成竖排单字。
- **会话头。** 标题行是一条不换行的 flex 行。注册方把控件堆在标题簇内部（模式路由、撤销、恢复、快照），实测在 310px 的行里占据 588px：控件席盖住了工具图标，并把自身末尾按钮裁到右边界之外。
- **宽表格。** 四列及以上的表格靠容器上的 `:hover` 才开启横向滚动；触屏没有 hover，右侧列无法触达。

## Decision

手机宽度（低于 768px，即 `ui-sidebar-right` 已经用于全屏面板的那个宽度）改用同一批组件的另一套排布：

**重新展开的侧边栏覆盖中栏而不占轨道。** `MOBILE_DRAWER_MAX = 768` 与 `SIDEBAR_AUTO_COLLAPSE` 并列放在 `columns.ts`。低于该值时，AppFrame 仍先按原逻辑解算列宽，然后把侧边栏轨道报为 0，并把该列渲染为绝对定位抽屉；抽屉宽度由组件算出（`min(84vw, 320px)`）并传给侧边栏 slot，因为覆盖态没有轨道可以读取宽度。抽屉下方是遮罩，点击经既有的 `toggleSidebar` action 关闭；抽屉打开时不渲染侧边栏拖拽手柄——没有轨道可拖。

**设置弹窗变成占满视口的单栏面板。** 导航栏变成同一批 `navCell` 按钮组成的横向滚动条带，位于内容区上方，内容区因此保持整宽，且不需要新增视图状态。关闭控件放大到 36px 触控目标。

**会话头变成横向滚动条带。** 标题行不再换行，改为横向滚动，每个控件席保持固有宽度；收缩它们只会把注册的控件挤回列内。面包屑上限降到 160px，头部左右内边距降到 12px。

**会话头角落席固定而非随条带滚动。** 该席位承载着重新打开已收起右栏的唯一控件。放进滚动条带后它落在 800 多像素宽头部的末端——390px 视口上 `x = 877`，既在屏幕外，也无法通过触控触达——因此手机宽度下将它锚定在头部的末端边缘，条带右侧为其预留 40px。它同时位于侧边栏抽屉遮罩之上，因此首次触摸即打开面板，而不会被当成"点击抽屉之外"。

**粗指针保持宽表格可滚动。** 在 `@media (hover: none)` 下，宽表格容器在静止状态即保持 `overflow-x: auto`，因为指针设备上开启滚动的 hover 揭示在触屏上永不触发。

**输入框只在键盘表面上获取焦点。** 输入框的解锁 effect 会在挂载与每次切换会话时把焦点交还草稿框——这是桌面端的读法，下一次击键就该落在刚打开的框里。在手机上，这次聚焦会弹出软键盘，盖住刚刚切过去的会话。判定采用白名单而不是触摸黑名单：只有 `(hover: hover) and (pointer: fine)` 命中**且** `navigator.maxTouchPoints` 为 0 时才聚焦。对触摸读数做黑名单恰好在最需要它的地方失效：处于桌面模式的手机浏览器会把指针媒体查询报成鼠标式，而 `maxTouchPoints` 始终如实反映硬件。点击输入框仍会聚焦，指针设备路径保持不变。

桌面几何未被触碰：所有改动都在视口或指针媒体查询内，且抽屉分支只存在于手机断点之下。

## Consequences

手机视口下，无论侧边栏开合，会话区都保持整宽；每个已注册的头部控件都可触达，而不是被裁切。手机上头部高 68px（桌面 76px），设置面板把整个区域给到单个分区。

代价：侧边栏抽屉覆盖内容而非与其共存，手机用户一次只能看会话或会话列表其中之一；头部条带需要横向滑动才能触达放不下的控件，用户首先看到的控件取决于条带停在哪里（即左端）；抽屉断点（768px）刻意与右栏的全屏判定共用同一数值，而非针对某一设备类型调校，因此 767px 窗口得到手机行为，768px 窗口不会。

## Alternatives considered

**继续挤压中栏。** 这是当前偏向桌面的行为；在 390px 下它只留 110px 会话宽度且无法阅读，正是本次改动要消除的现象。

**用 flex 换行或 grid 区域把会话头拆成两行。** 注册的控件是标题簇的子元素，而不是标题行的兄弟节点，因此给标题行加换行只重排它的三个直接子元素，标题簇仍然溢出。用 `display: contents` 溶解标题簇确实让控件成为标题行的网格项，但控件席的内容经 portal 渲染，实测行高 114px，而控件本身只有 28px。

**在手机上隐藏已注册的头部控件。** 框架无法判断注册方的哪些控件可以省略，隐藏它们只是移除功能，而不是重新安置。

**给设置弹窗做两级导航（列表，然后详情）。** 条带让每个分区都保持一次点击可达，且无需在面板里新增导航状态。
