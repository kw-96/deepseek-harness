# Agent Note: 从会话头停止单个后台任务

Status: implemented

[English](2026-09-14-session-job-stop-control.md) | 中文

## 问题

Web 端的后台任务面板只会列出某个会话的任务，对它们无能为力：[显示规则那份笔记](2026-08-08-web-background-job-display.zh.md)把它定为「给人看的只读投影」，而唯一的取消路径是面向模型的 `job_kill` 工具。于是卡住的任务——永不返回的 shell 命令、生产者不再推进的委派——只能等模型自己发现。会话头写着「1 个后台任务运行中」，却没有任何控制手段，而那一行还在不停计时。显示规则那份笔记把障碍写得很直白：`kill()` 会把终态投递标为已上报，所以照该契约写出来的人类中断，会让模型一直以为它的任务还在跑。

## 决策

会话头的任务列表在**运行中的行**上新增「停止」控件，由会话控制器新增的 `session/killJob` Remote 方法支撑。

- `SessionCommandController.killJob(sessionId, jobId, reason?)` 从 Agent 注册表解析该会话的在世 Agent，套用所有会话命令共用的子代理归属拒绝，然后调用 `ctx.jobs.kill(jobId, agent, reason)`。传入 Agent 就是归属栅栏：注册表会拒绝属于别的会话的任务，因此一个会话的头永远无法取消另一个会话的工作。
- jobs 服务按**可选**读取（`ctx.get('jobs')`）。某个部署挂了会话 API 但没挂后台任务注册表时，得到的是 `session/job-not-found`，而不是让整个控制器因为一个它并不需要的服务一直挂起。
- **拥有者会被告知。** 因为 `kill()` 会把终态投递标为已上报，注册表不会为它取消掉的任务再发完成通知。命令因此自己向拥有该任务的 Agent 注入一条插件来源的通知（`session-controller`，form 为 `notice`）：忙碌的拥有者会在下一步收到，空闲的拥有者会在下一次提示时收到。这正是显示规则那份笔记当年悬置、并因此选择只读的那个决策。
- 注册表自己的结果如实返回：取消到运行中的任务是 `requested`，遇到已结束的是 `already-finished`。客户端用**已有的**注册表帧渲染行，因此那一行会先变成 `stopping`，随后进入终态，无需重新拉取。
- 浏览器侧注入一个绑定会话的 `stopJob(jobId)` face，自身不持有状态：点击就是一次 RPC，权威状态沿既有的 `jobs` 控制帧回来。

## 考虑过的替代方案

- **扩展现有 `cancel`。** 取消任务与取消回合是两种不同的操作，quiescence 含义也不同：回合取消会中止模型流并保留收件箱，任务取消只终止一个生产者并释放它的等待者。合成一个端点就得靠判别字段分支，而两者没有共享行为。
- **让 jobs 插件把 `job_kill` 直接暴露给浏览器。** jobs 系列包拥有注册表与面向模型的工具，但没有挂任何 Remote 命名空间；而会话控制器本来就是发布按会话任务帧、持有会话寻址命令的 BFF。
- **保持面板只读，把请求交给模型转达**（让模型去停）。这正是此前该面板逼出来的做法：它依赖一个进行中的回合、依赖模型配合——而任务卡住时，这两者恰好都不可用。

## 后果

- 操作者不必等模型配合、也不必等启动该任务的那个回合结束，就能终止一个运行中的后台任务。
- 该控件只停**一个任务**：它不停回合、不清队列、也不改变会话记录的走向——那些仍归输入框的停止按钮与队列坞。
- 被拒绝或未知的任务会让该行保持运行中的状态，而不是给出虚假的成功；失败表现为「什么都没变」，且不会弹提示，因为这个界面自身没有错误通道。
- 无视取消信号的任务会一直报告 `stopping` 直到其生产者结束；注册表把这种状态标为「已请求停止」，而不会假装它已经结束。
- 那条注入通知是模型得知「有人结束了它的任务」的唯一信号，因此当拥有者空闲时被杀掉的任务，要等它下次运行才会被确认。

## 测试

`packages/api/session-controller/tests/commands-kill-job.host.spec.ts` 在真实的会话、Agent 与任务注册表上驱动该命令：运行中的任务返回 `requested`、把操作者的 reason 送到生产者的 `cancel`，并恰好注入一条插件来源通知；已结束的任务返回 `already-finished`，不取消也不通知；未知 id 与无注册表的部署都抛 `session/job-not-found`；未挂载的会话抛 `session/not-found`；子代理归属的会话被拒绝。`packages/client/ui-jobs/tests/job-list-action.client.spec.tsx` 覆盖运行中行上的控件、`stopping` 时的禁用态，以及已结束行上不出现控件；插件规格断言声明的服务与头部注册。
