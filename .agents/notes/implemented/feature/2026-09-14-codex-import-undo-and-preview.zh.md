# Agent Note: Codex 导入的撤销与只读预览

Status: implemented

[English](2026-09-14-codex-import-undo-and-preview.md) | 中文

## 问题

一次导入 sweep 会写入 DSH 会话、对账工作区与项目，却不留下任何让操作者收回这些动作的东西。误导入一份 Codex 存储、或者想在写入前先知道 sweep 会做什么的用户，手上只有一个 **立即导入** 按钮：第一次反馈出现在会话已经存在之后，而撤销意味着去侧栏里逐个归档这些导入会话。导入历史记录了每轮创建了哪些会话，却只把它们以标题形式藏在折叠项里。

## 决策

`codexImport` Remote 新增 `scan()`、`undo(at)` 与 `restore(at)`，设置卡片把它们暴露出来：**预览** 按钮渲染下一轮 sweep 的逐线程判定，每条导入记录带 **撤销** 与 **恢复** 按钮以及「已撤销」标记。

`scan()` 在不写入会话、工作区、项目与历史条目的前提下报告下一轮 sweep 会做什么。它与 sweep 共用同一套枚举与快照构造，因此预览不可能与它描述的那次执行不一致。sweep 通过写入隐式完成的分类现在显式化了：`CodexImportReconciler.classify()` 读取已存储的会话头与事件，在不触碰存储、live store 与工作区的情况下返回 `imported`、`updated`、`unchanged` 或 `deferred-active`。

`undo(at)` 把某轮记录创建的会话全部归档，并给该轮记录打上 `undoneAt`；`restore(at)` 取消归档并清除该标记。DSH 没有持久化会话删除能力，而归档本身就是它可逆的会话生命周期（[可逆会话归档](2026-09-11-reversible-session-archive-and-auto-archive.zh.md)），因此撤销不删除任何证据、不触碰会话日志，并且随时能从侧栏「归档」分组里恢复。工作区注册表已经不再认识的会话会被计入返回的 `failed` 并跳过，而不会中断同一轮里其余会话的处理；对从未记录过的轮次时间戳发起撤销会被拒绝。

标记存放在持久化的轮次记录里，卡片在撤销或恢复之后会重读历史，因此两个标签页、一次刷新、乃至另一台机器对「某轮是否已撤销」的看法一致。

## 考虑过的替代方案

- **直接删除导入的会话。** DSH 没有暴露会话删除能力；插件内自行删除就得绕过持久化、索引与投影缓存几层去动日志文件。对一个核心诉求是安全的特性而言，这条路被否决。
- **给 `runImportSweep` 加 dry-run 开关。** 那样一个函数会同时决定「写什么」与「报告什么」，而且该开关还得单独守住项目对账——那是 sweep 唯一在会话存储之外写入的部分。改为让两个调用方共享一个显式的 `classify()`。
- **只把撤销标记留在卡片状态里。** 浏览器刷新即遗忘，多标签页与多机器之间还会互相矛盾。

## 后果

- 操作者可以预览一次导入、也可以撤销一次，而被撤销的会话把证据保留在 DSH 里。
- **预览与它所描述的 sweep 同价**：它会读取每个已存储会话的会话头与事件日志，受同样的上限约束。这是「永不与执行结果不一致」的代价。
- 撤销不会阻止后续 sweep：已撤销轮次的会话按 `unchanged` 对账，或追加 Codex 的新内容——那些内容保持归档且不可见。这可接受，因为 sweep 从不取消归档，而 `restore` 会把当前内容重新呈现出来。
- 在某一台机器上撤销，是「对这个存储撤销」而非「对 Codex 源撤销」：下一轮 sweep 不会重复导入，因为导入会话仍然存在。

## 测试

`packages/session/session-import-codex/tests/loader-composition.spec.ts` 走真实 Loader 组合。预览用例断言计数与逐线程判定，并断言没有写入任何会话、工作区或历史条目；随后在真实 sweep 之后再跑一次 `scan()`，期望每个线程都读作 `unchanged`。撤销用例断言两个会话都进入 `archivedSessionIds`、标记在重载后仍然存在、重复撤销为空操作、`restore` 同时清空归档集合与标记。控制器与卡片规格覆盖预览按钮、判定面板、已撤销标记以及撤销/恢复回调。
