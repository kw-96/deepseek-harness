# Agent Note: Codex 导入历史折叠与滚动

Status: implemented

[English](2026-09-08-codex-import-history-collapsible.md) | 中文

## Problem

Web **插件**设置标签中的 Codex 导入卡片把全部持久导入历史内联渲染：每条历史运行都平铺其导入会话与逐会话「打开」按钮。一轮导入大量线程（报告案例仅活跃延后就达 14 项）或历史运行不断累积，都会把设置面板越撑越高，把面板固定区和其余插件卡片挤出视野。

## Decision

卡片把历史列表限定在 240 像素高的内部滚动列中，长历史不再拉高面板。每轮产生会话变更的运行改为可折叠：运行头（时间戳加结果计数）是切换会话列表的按钮，chevron 原语图标作为展开提示，`aria-expanded` 承载状态。最新一轮默认展开，导入新产生的一轮置顶时也自动展开；无会话变更的运行保持静态运行头加「本轮没有会话变更」提示。折叠状态是按键位索引的卡片本地 React 状态，无需新增界面文案。

## Alternatives considered

**仅加滚动容器。** 不采用：能限制总高，但单轮大量会话仍完整铺开，面板依旧被最新一轮导入主导。

**仅做逐轮折叠、不限制总高。** 不采用：运行轮次变多后仍会拉高面板；内部滚动列让总高与轮次数量解耦。

**为整个「导入历史」区块做一个总折叠。** 不采用：把用户导入后最想看的最新一轮计数也藏到了额外一次点击之后。

**使用原生 `<details>` 元素。** 不采用：其非受控 open 状态会在 React 重渲染时被重新施加，组件测试也更难断言；显式 `aria-expanded` 按钮与设置界面已有的 PluginCard 折叠模式一致。

## Consequences

历史区高度不超过 240 像素，设置面板保持视口限定的固定高度，只有面板自身的选项区滚动。每轮会话列表一次点击即可展开，折叠时计数仍可见。组件测试覆盖最新轮默认展开、旧轮折叠与展开、新轮置顶自动展开。本包现以值导入 `ui-primitives`（基线外部依赖，加入 `devDependencies`）与 `clsx`（加入 `dependencies`），并为既有的类型导入补上了 `ui-renderer` 的 `devDependencies` 声明。
