## 静态资源缓存策略与压缩级别（用户要求按方案 B 落地）

- 背景：手机经 Tailscale 首次打开 Web 界面很慢。实测定位到两条：① 主因是 Tailscale 未打成直连（`direct connection not established`，往返 450 毫秒以上、偶发超时，走 DERP 中继）；② 次因是 Vite 产物（`/assets/<名字>-<hash>.<扩展名>`）只带 `content-type` 响应头，没有 `Cache-Control`／`ETag`／`Last-Modified`，每次刷新都重新下载；而占 5 MB（gzip 后）大头的插件 bundle 路由本就带 `rev` 与 `immutable`。
- 处置：`serveStatic` 只对匹配 `/assets/<名字>-<hash>.<扩展名>` 的路径追加 `Cache-Control: public, max-age=31536000, immutable`，其余路径（index、不带 hash 的文件）一律不带缓存指令；部署的 webserver 行把 `compressionLevel` 由 1 提到 6。插件 bundle 路由与既有行为保持不动。
- 验证：`frontend-static` 包的真实组合用例 2 项全部通过（新增 1 项断言带 hash 的产物发 immutable、`/assets/plain.js` 与 `/app.js` 不发缓存头）；host 侧重建产物已含新逻辑；配对记录重录后待复核。
- 影响范围：`packages/host/frontend-static`（实现、测试、双语 README、配对记录）、新增 Agent Note，以及本机 profile 的 webserver 压缩级别。缓存头只改浏览器缓存语义，不涉及路由、鉴权与 SSE 推送。

## 用腾讯云服务器自建 DERP 中继（用户要求）

- 背景：手机经 Tailscale 访问 DSH 慢——实测走海外中继（`via DERP(syd)` 450 毫秒以上、偶发超时）。用户提出用手上的腾讯云服务器做中转；先澄清「Tailscale 的 DNS 设置只做名字解析，改不了数据路径，能做中转的是 DERP」，并排除 exit node（只作用于访问公网的流量）。
- 落地：① **安全组收窄**——补 80/443/987/888/12765 五条规则后删掉 `0.0.0.0/0 ALL 允许`，MySQL 3306 与 FTP 21 由此与公网隔离（改前后实测对照）；② **服务器侧**装 Go 1.25.5（阿里云镜像）编译 derper 1.102.4，复用宝塔那张含 `taqu.team` 的证书做软链（续期自动跟随），systemd 服务监听 8443/tls 与 3478/udp，firewalld 放行两条（未 reload）；③ **Tailscale ACL** 顶层加 `derpMap`（regionID 900、hostName `taqu.team`、derpPort 8443、stunPort 3478，保留官方区域兜底）。
- 排障：客户端一度报 `Relay server unavailable`——根因是 derper 的 `-verify-clients=true` 有前提：它靠 derper 主机**本地** tailscaled 的 localapi（`/var/run/tailscale/tailscaled.sock`）查询客户端身份，而该服务器未装 Tailscale，于是所有客户端连接被拒；改为 `false` 后恢复。
- 结果：`netcheck` 最近中继变成 taqu（52 毫秒，原 syd 223 毫秒）；端到端 `via DERP(taqu)` 83–255 毫秒且零超时；实测已传输 6.6 MB（页面数据确实走广州中继）；手机改用新客户端后设备名从 `huawei-slg-w10` 变为 `slg-w10`。
- 影响范围：腾讯云安全组、该服务器的 derper 服务与防火墙、Tailscale ACL；**未改动站点 nginx、数据库与业务**。
- 补做（同日）：按用户要求给该服务器装 tailscaled 1.102.4（静态包 + 自写 systemd 单元，`--accept-dns=false`/`--accept-routes=false`，加入 tailnet 成为 `taqu-derp` 100.76.46.42），derper 随即改回 `-verify-clients=true`，日志中不再出现 rejected；`/etc/resolv.conf` 未被改动，站点 DNS 与业务无感。坑：`tailscale up --authkey` 经 ssh stdin 传参会**丢一个字符**（本机 61 字节、服务器只收到 60）并报 `invalid key: unable to validate API key`，改用 base64 传输后成功。
- 附带：为给手机装新版 Tailscale，曾把官方 APK（100.5 MB，sha256 与官方一致）临时放在站点静态别名目录下提供下载，用户下载完成后已删除（公网 URL 现为 404）。

## 让 taqu 反代本机 DSH，对外提供公网 HTTPS（用户思路）

- 背景：手机经 Tailscale 访问 DSH 时反复「无法访问此网站」，但服务端侧已全部排除（本机看到手机的 TCP 连接、从 tailnet 内其他设备模拟手机浏览器请求返回 200、完整下载 79 KB 页面与 566 KB bundle 均正常）。用户提出：taqu 已是 tailnet 节点，直接让它反代本机 3080 再对外提供 HTTPS。
- 落地：① 在 taqu 的 nginx 新增独立文件 `/www/server/panel/vhost/nginx/dsh-proxy.conf`（`listen 8444 ssl`，复用 taqu.team 现有证书），反代到 `http://100.123.104.22:3080`（经 Tailscale，实测服务器↔本机为**直连 50 毫秒**）；② 把 Host/Origin 重写为直连地址以通过 DSH 的 `/api` 信任围栏，并开启 WebSocket/SSE、关闭代理缓冲；③ firewalld 放行 8444，安全组由用户放行。
- 验证：外网 `https://taqu.team:8444/` 返回 200（79,720 字节 / 0.72 秒），566 KB 资源 1.69 秒；用户手机访问成功进入 DSH（无需开 Tailscale）。
- 为何不能做成子路径（`taqu.team/dsh`）：DSH 前端由 `frontend-static` 注入 `<base href="/">`，资源与 `/plugins/*` 都从站点根加载；且该站点的 `/api` 已反代到 .NET 后端；DSH 没有 base-path 配置项。想要不带端口的地址只能走子域名（443 + SNI 分流）。
- 影响范围：taqu 的 nginx（仅新增一个文件，未改动现有两个 server 块）、firewalld、腾讯云安全组；本机与 Tailscale 侧无改动。该地址**公网可达**，认证目前只靠 `dsh-remote-mobile` 的门禁；如需更强可叠 nginx basic auth 或改走子域名再加鉴权。

## 子域名入口 dsh.taqu.team + Basic Auth，并修掉 8444 的无认证裸奔（用户要求）

- 背景：用户要「不带端口」的地址并要一套账号密码；排查中发现上一步的 8444 入口**没有任何认证**——公网请求直接拿到 200 与完整 79,720 字节页面，根因是 `dsh-remote-mobile` 把 taqu 反代来源（100.76.46.42，Tailscale 网段）当成免密直连放行。
- 处置：① 先给 8444 立即加 nginx Basic Auth 止血；② 用户加好 `dsh.taqu.team` 的 A 记录后，用 acme.sh（webroot 模式，复用站点 80 上的 `/.well-known` 通道）签发 Let's Encrypt 证书并安装到 `/www/server/panel/vhost/cert/dsh.taqu.team/`（自动续期已写入 acme 定时任务）；③ `dsh-proxy.conf` 扩成两个 server 块（8444 与 443 的 `dsh.taqu.team`，nginx 按 SNI 分流，现有站点那两个 server 块一行未动），均带 Basic Auth 与 WebSocket/SSE 支持。
- 排障：Basic Auth 一度返回 500，nginx `error.log` 给出根因 `open() "…/.htpasswd_dsh" failed (13: Permission denied)`——htpasswd 属主是 root 而 nginx worker 以 www 运行，`chown www:www` 后恢复。
- 验证：服务器本地与公网两侧一致——`https://dsh.taqu.team/` 与 `https://taqu.team:8444/` 无凭据 401、带凭据 200；凭据（用户名 `dsh`）写在服务器 `/root/dsh-basic-auth.txt`，不进聊天记录。
- 遗留：`dsh-remote-mobile` 的配对页目前对 taqu 来源仍免密（可在 DSH 面板关闭「Tailscale 免密直连」改成两层认证）；影响范围仅 taqu 的 nginx 配置与证书目录。

- 背景：用户反馈面板画面模糊，并对比 Codex 内嵌浏览器的自然观感。根因是两种形态的差异——Codex 是桌面应用的原生嵌入渲染，而 Web 面板只能走 CDP 图像流（截帧→压缩→传输→重绘），远程访问还会叠加网络损耗。
- 处置：提高图像质量与帧率上限、收紧视口同步阈值以保证像素一一对应，并把画质开放为面板可传参数。
- 验证：三个改动文件语法检查通过；冒烟测试通过（宿主半 8 条路由与 3 个工具、右栏注册契约不变）。
- 影响范围：`community/plugins/packages/browser-panel`；宿主侧改动需重启生效。
- 待办：根治画质需让面板跑在能原生嵌入浏览器的桌面壳里（Electron webview 或 Tauri 多 webview），属结构性改动，本次未做。

## 修复右栏在 768-996px 视口下打不开（用户报告续）

- 背景：用户反馈「能看到右侧栏入口但点击没有展开」。查得该设备 UA 为桌面模式（Tablet/Windows NT + ArkWeb），视口约 980px，正落在 768-996px 区间：此时框架解算 details 轨道为 0（canShow=false），而右栏仅在低于 768px 时才自动全屏，于是打开后在同一 commit 内被收起，表现为点击无效。
- 处置：无轨道（视口低于 768px 或 canShow 为假）一律以全屏呈现，删除"打开即收起"的判定；track 语义保持不变。另把手机会话头的角落席置于抽屉遮罩之上，避免抽屉展开时首次触摸被遮罩吞掉。
- 验证：980x844 视口下真实触摸 → 右栏全屏打开（此前 rightOpen=false）；390 视口抽屉展开时触摸角落席 → 一次点击即打开右栏；ui-sidebar-right 与 ui-conversation 共 565 项测试全绿；客户端类型检查通过。
- 影响范围：packages/client/ui-sidebar-right（呈现判定、测试与双语 README）、ui-conversation（角落席层级）；新增一篇 Agent Note 并更新既有手机适配 Note。
