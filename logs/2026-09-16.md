## 静态资源缓存策略与压缩级别（用户要求按方案 B 落地）

- 背景：手机经 Tailscale 首次打开 Web 界面很慢。实测定位到两条：① 主因是 Tailscale 未打成直连（`direct connection not established`，往返 450 毫秒以上、偶发超时，走 DERP 中继）；② 次因是 Vite 产物（`/assets/<名字>-<hash>.<扩展名>`）只带 `content-type` 响应头，没有 `Cache-Control`／`ETag`／`Last-Modified`，每次刷新都重新下载；而占 5 MB（gzip 后）大头的插件 bundle 路由本就带 `rev` 与 `immutable`。
- 处置：`serveStatic` 只对匹配 `/assets/<名字>-<hash>.<扩展名>` 的路径追加 `Cache-Control: public, max-age=31536000, immutable`，其余路径（index、不带 hash 的文件）一律不带缓存指令；部署的 webserver 行把 `compressionLevel` 由 1 提到 6。插件 bundle 路由与既有行为保持不动。
- 验证：`frontend-static` 包的真实组合用例 2 项全部通过（新增 1 项断言带 hash 的产物发 immutable、`/assets/plain.js` 与 `/app.js` 不发缓存头）；host 侧重建产物已含新逻辑；配对记录重录后待复核。
- 影响范围：`packages/host/frontend-static`（实现、测试、双语 README、配对记录）、新增 Agent Note，以及本机 profile 的 webserver 压缩级别。缓存头只改浏览器缓存语义，不涉及路由、鉴权与 SSE 推送。

## 用腾讯云服务器自建 DERP 中继（用户要求）

- 背景：手机经 Tailscale 访问 DSH 慢——实测走海外中继（`via DERP(syd)` 450 毫秒以上、偶发超时）。用户提出用手上的腾讯云服务器做中转；先澄清「Tailscale 的 DNS 设置只做名字解析，改不了数据路径，能做中转的是 DERP」，并排除 exit node（只作用于访问公网的流量）。
- 落地：① **安全组收窄**——补 80/443/987/888/12765 五条规则后删掉 `0.0.0.0/0 ALL 允许`，MySQL 3306 与 FTP 21 由此与公网隔离（改前后实测对照）；② **服务器侧**装 Go 1.25.5（阿里云镜像）编译 derper 1.102.4，复用宝塔那张含 `taqu.team` 的证书做软链（续期自动跟随），systemd 服务监听 8443/tls 与 3478/udp，firewalld 放行两条（未 reload）；③ **Tailscale ACL** 顶层加 `derpMap`（regionID 900、hostName `taqu.team`、derpPort 8443、stunPort 3478，保留官方区域兜底）。
- 排障：客户端一度报 `Relay server unavailable`——根因是 derper 的 `-verify-clients=true` 有前提：它靠 derper 主机**本地** tailscaled 的 localapi（`/var/run/tailscale/tailscaled.sock`）查询客户端身份，而该服务器未装 Tailscale，于是所有客户端连接被拒；改为 `false` 后恢复。
- 结果：`netcheck` 最近中继变成 taqu（52 毫秒，原 syd 223 毫秒）；端到端 `via DERP(taqu)` 83–255 毫秒且零超时；实测已传输 6.6 MB（页面数据确实走广州中继）；手机改用新客户端后设备名从 `huawei-slg-w10` 变为 `slg-w10`。
- 影响范围：腾讯云安全组、该服务器的 derper 服务与防火墙、Tailscale ACL；**未改动站点 nginx、数据库与业务**。遗留：`verify-clients=false` 期间任何人都能把该端口中继（消耗 5M 带宽），可选补装 tailscaled 后改回 `true`；用户应撤销临时提供的 Tailscale API key。
- 附带：为给手机装新版 Tailscale，曾把官方 APK（100.5 MB，sha256 与官方一致）临时放在站点静态别名目录下提供下载，用户下载完成后已删除（公网 URL 现为 404）。
