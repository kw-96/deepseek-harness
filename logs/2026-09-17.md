## 修复桌面壳内点击会话链接无反应

- 现象：在桌面壳的会话里点击 http(s) 链接毫无反应，既不跳转系统默认浏览器，也没有任何提示。
- 定位：外链按 `target="_blank"` 渲染，点击走的是 WebView2 的新窗口请求；Tauri 默认拒绝该请求，而壳的导航钩子只覆盖同窗口导航，于是点击落在两条接管路径之外。前端原有的拦截器只认全局 API 面的 core，取不到就直接放弃，既没有第二条通道也没有出口兜底。上一轮的"接线遗漏"判断不准：标题栏本就调用该拦截器，真正的缺口在通道与出口。
- 处置：前端改用与标题栏一致的壳判定作为入口，补齐 IPC 原语通道，并在两条 IPC 面都不可用时退回同窗口导航交给导航钩子；壳侧新增新窗口请求处理，外链交给系统默认浏览器、壳内地址留在壳内新建窗口，主窗口相应改为在启动阶段创建。
- 验证：外链出口单测 7 项通过（覆盖全局 API 面、IPC 原语面、无 IPC 面兜底、命令被拒兜底四条分支）；`cargo check` 与整仓类型检查通过；重建客户端产物后服务返回的模块修订号由 `d0489c8ead4e` 变为 `6dabb3c9a7be`，产物内已含新代码；重建壳可执行文件后其二进制内含新增的诊断串。
- 影响范围：`packages/client/ui-layout`（前端拦截与单测）、`packages/experimental/web-desktop/src-tauri`（新窗口出口、主窗口创建、窗口配置）；前端刷新页面即生效，壳侧改动需重新构建并重启壳。

## 修复右栏在 768-996px 视口下打不开（用户报告续）

- 背景：用户反馈「能看到右侧栏入口但点击没有展开」。查得该设备 UA 为桌面模式（Tablet/Windows NT + ArkWeb），视口约 980px，正落在 768-996px 区间：此时框架解算 details 轨道为 0（canShow=false），而右栏仅在低于 768px 时才自动全屏，于是打开后在同一 commit 内被收起，表现为点击无效。

## 触屏设备切换会话不再自动聚焦输入框（用户报告）

- 背景：用户反馈手机上切换会话时输入框被持续聚焦，软键盘自动弹出挡住会话内容。
- 定位：ui-conversation 输入栏的解锁 effect 依赖 sessionId，挂载与每次切会话都会把焦点交还草稿框（桌面端设计）。
- 处置：上报 (hover: none) 或 (pointer: coarse) 的设备在该 effect 中不聚焦；点击输入框仍正常聚焦，指针设备行为不变。
- 验证：触摸模拟下逐步实测（加载/开抽屉/打开会话/切换会话）焦点始终不在输入框；同页面把 hover 判定改为指针模式后切换会话即恢复聚焦（对照实验）；新增一条触摸用例，input-bar 89 项测试全绿；客户端类型检查通过。
- 影响范围：packages/client/ui-conversation（输入栏与其测试），并更新既有手机适配 Agent Note 双语两侧。

## 输入框自动聚焦判定改为白名单（用户报告续）

- 背景：上一版用 (hover: none)/(pointer: coarse) 判定触屏；用户反馈切到已停止的会话不再弹键盘，但切到仍在运行的会话仍会聚焦弹键盘——桌面模式的手机浏览器会把指针媒体查询报成鼠标式，黑名单判定恰好在最需要它的场景失效。
- 处置：改为白名单——只有 "(hover: hover) and (pointer: fine)" 命中且 navigator.maxTouchPoints 为 0 时才自动聚焦。
- 验证：模拟桌面模式误报（指针媒体查询为真、maxTouchPoints=5）后切换到运行中的会话，焦点不在输入框；新增一条「桌面模式触摸屏」用例，input-bar 90 项测试全绿；客户端类型检查通过。
- 影响范围：packages/client/ui-conversation（输入栏与其测试），并更新手机适配 Agent Note 双语两侧。

## 修复 DeepSeek 请求扩展准备失败（0.1.6 新增包不在运行时依赖闭包）

- 现象：Web 会话发消息报「DeepSeek request extension preparation failed」，整轮 DeepSeek 请求被中断（与 2026-09-11 同款）。
- 定位：报错来自 packages/llm/plugin-package-inventory-deepseek——DeepSeek 请求扩展的「插件包清单」在每次请求前收集活动 Host 插件条目并逐个解析所属包，任何一个解析不到就抛出 cannot resolve active package，整轮请求随之失败。核对后发现 v0.1.6-alpha.1 新增的 8 个带 Host 面的官方插件在 apps/cli 的运行时依赖里全部缺失、模块回退目录（~/.dsh/profiles/node_modules，234 个包）也没有它们：dsh-client-ui-sidebar-right、dsh-client-ui-sidebar-files、dsh-client-ui-sidebar-terminal、dsh-client-ui-sidebar-documentpreview、dsh-client-ui-open-in-app、dsh-client-ui-settings-unarchive-sessions、dsh-compaction-image-offload、dsh-ptc-runtime-node。它们分别由 web-app 与 base bundle 的补丁层声明为活动条目，因此必然参与解析。
- 处置：与 9/11 同一手法，把这 8 个包补进 apps/cli 的 dependencies 并 pnpm install，使其进入安装闭包；app-boot 会在下次启动时重建模块回退目录中的链接。
- 验证：解析自检从 13 个失败降到 5 个，剩余 5 个（dsh-client-file-upload、dsh-client-resources、dsh-host-open-in-app、dsh-api-terminal-controller、dsh-api-workspace-files）均无 Host 面、不参与包清单；web-app 与 base 两个 bundle 中所有带 Host 面的活动条目现已全部可解析。
- 生效条件：需重启 dsh web（回退目录链接在启动时重建）。
