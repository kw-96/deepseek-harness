- 背景：用户反馈在桌面壳中点击对话里的链接从不跳转系统默认浏览器。该功能 9-11 就已做原生出口与前端拦截，但一直没生效。

- 影响范围：`packages/client/ui-layout`（源码与 dist 产物）；需重启生效。

## 修复桌面壳内点击会话链接无反应

- 现象：在桌面壳的会话里点击 http(s) 链接毫无反应，既不跳转系统默认浏览器，也没有任何提示。
- 定位：外链按 `target="_blank"` 渲染，点击走的是 WebView2 的新窗口请求；Tauri 默认拒绝该请求，而壳的导航钩子只覆盖同窗口导航，于是点击落在两条接管路径之外。前端原有的拦截器只认全局 API 面的 core，取不到就直接放弃，既没有第二条通道也没有出口兜底。上一轮的"接线遗漏"判断不准：标题栏本就调用该拦截器，真正的缺口在通道与出口。
- 处置：前端改用与标题栏一致的壳判定作为入口，补齐 IPC 原语通道，并在两条 IPC 面都不可用时退回同窗口导航交给导航钩子；壳侧新增新窗口请求处理，外链交给系统默认浏览器、壳内地址留在壳内新建窗口，主窗口相应改为在启动阶段创建。
- 验证：外链出口单测 7 项通过（覆盖全局 API 面、IPC 原语面、无 IPC 面兜底、命令被拒兜底四条分支）；`cargo check` 与整仓类型检查通过；重建客户端产物后服务返回的模块修订号由 `d0489c8ead4e` 变为 `6dabb3c9a7be`，产物内已含新代码；重建壳可执行文件后其二进制内含新增的诊断串。
- 影响范围：`packages/client/ui-layout`（前端拦截与单测）、`packages/experimental/web-desktop/src-tauri`（新窗口出口、主窗口创建、窗口配置）；前端刷新页面即生效，壳侧改动需重新构建并重启壳。
