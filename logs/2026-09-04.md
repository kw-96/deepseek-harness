# 2026-09-04 修改日志

## 修复 `pnpm dsh web` 插件树加载失败

- 现象：`dsh web` 启动时报 `failed to import loader entry dsh-doc`，提示找不到原生绑定 `xberg-node.win32-x64-msvc.node`。
- 原因概述：`dsh-doc` 依赖的 `@xberg-io/xberg@1.0.14` 引用了未发布的 Windows 平台原生包，导致 Windows 上原生绑定缺失。
- 处理概述：调整 `web` profile 的依赖解析，使 `dsh-doc` 能加载到可用的原生绑定；重装 profile 依赖后验证 `dsh-doc` 可正常加载，`pnpm dsh web` 可正常启动。

## 新增 web profile 环境引导脚本

- 目的：让另一台主机 clone 仓库后能一键复现 `web` profile 的环境，避免重新踩到上述原生绑定缺失问题。
- 概述：新增 `scripts/setup-web-profile.mjs`，负责在目标主机上初始化 `web` profile、补齐依赖解析配置并安装外部插件。
- 验证：已在隔离的临时 DSH_HOME 下端到端验证通过，产出 profile 可完整启动 `dsh web`。

## 安装插件管家 dsh-plugin-manager

- 概述：向 `web` profile 安装 `dsh-plugin-manager@0.1.0`（Web 插件管家，可检查、启用、禁用、分组管理运行时插件），并作为 bundle 加入 `dsh.profile.bundles`。
- 处理概述：执行 `dsh plugin --profile web add dsh-plugin-manager` 完成依赖安装；期间发现会话内 `DSH_HOME` 环境变量被先前测试污染导致首次误装到临时目录，已清除该变量并重装到正确的 `~/.dsh/profiles/web`。
- 注意点：`dsh plugin add` 在 Windows 下 pnpm 完成后 `spawnSync` 因继承的 stdio 句柄未关闭而挂起，`reconcilePlugins` 未能自动执行，已手动将 `dsh-plugin-manager` 追加进 `bundles`。
- 验证：`pnpm dsh web` 正常启动，`dsh-plugin-manager` 加载无报错。
