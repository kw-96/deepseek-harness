# 2026-09-11 修改日志

## 修复 DeepSeek 请求扩展准备失败（REQUEST_EXTENSION）

- 现象：Web 会话发送任意消息即报「DeepSeek request extension preparation failed」，整轮 DeepSeek 请求被中断。
- 根因：web profile 补丁层插入了主进程插件 @deepseek-ai/dsh-session-import-codex，但该包仅作为若干前端包的 devDependency 存在，未进入 dsh 安装的运行时依赖闭包。开发态由 tsx 的 tsconfig 路径映射兜底完成加载，Loader 条目因此激活；而默认启用的请求扩展包清单插件用 Node 原生解析（createRequire.resolve.paths）逐个校验活动条目所属包，解析不到该包便抛错，导致整轮请求失败。同时 $DSH_HOME/profiles/node_modules 下遗留了指向已消失目标的同名悬空链接。
- 处置：把 @deepseek-ai/dsh-session-import-codex 纳入 apps/cli 的运行时依赖（与同样由 profile 补丁行引用的 dsh-terminal、dsh-terminal-bash 保持一致），执行 pnpm install 生成安装闭包链接；重启 dsh web 后，profile 模块回退目录下的同名链接被自动修复为有效目标。
- 验证：profile 组合中的 162 个裸插件包已全部可被 Node 原生解析（修复前为 161/162）；dsh web 正常启动并输出访问地址。
- 备注：源码与依赖改动需重启 dsh web 后生效。

## 加固模块回退链接的自愈校验（悬空链接）

- 背景：原有自愈判定只核对链接指向是否与解析结果一致，未核对目标是否仍然存在；当某个已声明依赖在磁盘上消失时，其历史遗留的悬空 symlink 会被误判为「已就绪」，从而长期滞留，正是本次故障的残留形态。
- 处置：模块回退目录的「就绪」判定增加悬空检查——属于当前安装闭包已声明但不可解析依赖的悬空 symlink 视为未就绪，在跨进程写锁内清理；仍可解析的链接、未声明的外部链接以及其他 profile 的链接均不在清理范围内。
- 验证：packages/boot/app-boot 的 profile 单测 42 项全部通过（含新增 2 项：悬空链接被清除且不重复生成、已安装依赖的悬空链接被重新指向）。

## 修复桌面壳启动失败只报「等待超时」

- 现象：双击根目录 `DeepSeek Harness.exe` 弹出「timed out after 180s waiting for `dsh web: http...`」，启动页不给出任何真实原因。
- 根因：`dsh web` 在打印就绪地址之前退出时，壳仍走超时分支并固定输出 180 秒文案，丢弃了子进程留在输出管道里的失败信息。本次实测该退出来自 3080 端口已被另一个 `dsh web` 占用（EADDRINUSE）。
- 处置：就绪等待区分「超时」与「子进程提前退出」；失败信息附上子进程退出状态与其输出末尾（含首个 `Error:` 行），不再把提前退出谎报成超时。
- 验证：端口被占用时新壳输出「dsh web exited (exit code 1) before printing `dsh web: http...`」并附 EADDRINUSE 那一行；端口空闲时正常启动并导航到 Web 界面。
- 产物：已重建并更新根目录 `DeepSeek Harness.exe`（壳源码未改启动流程，仅改失败诊断）。
