## workorder-agent：POPO 通道统一为机器人应用，并支持真 @ 提单人

- 背景：用户要求通知统一走机器人应用 API（应用 `Agent小奈`，App ID 683514698），删除自定义群机器人通道，并把缺项提醒改为真正 @ 到提单人。
- 契约要点（探测得出并已实测）：`POST /open-apis/robots/v1/token` 以 `{appId, appSecret}` 换 accessToken；调用带 `Open-Access-Token` 头；发送为 `POST /open-apis/robots/v1/im/send-msg`，`message` 必须是对象（text 取 `{content, atUids?, isAtAll?}`）——传字符串会让服务端返回 `500 服务繁忙`；错误码 `65338` 超长、`65605` 类型不支持、`65611` 接收人不可解析、`65612` 不在可见范围。
- 处置：
  - 删除自定义群机器人客户端与相关配置（`popoWebhookUrl`、`popoWebhookSecret`、`popoMode`），引导页字段改为机器人应用 App ID / App Secret / 接收人；控制面「设置」页改为显示「POPO 机器人应用 / 消息接收人」。
  - 提单人邮箱入库（`issues.submitter_email`，schema 升到 7）：易协作详情、列表行与 Webhook 载荷的 `author.mail` 三处都取；合并写入时为空不覆盖既有值。
  - 缺项提醒文案改为按邮箱生成 `@ 邮箱` 占位并回传 `atUids`，无邮箱时回退姓名文本且不 @；@ 列表随消息任务持久化（`message_tasks.at_uids_json`），只随首段发送，续发时从任务记录恢复。
  - 固定测试通知改为按配置接收人生成：邮箱接收人带 @ 占位，群 ID 接收人不带。
- 验证：插件 81 项测试全绿（新增 3 项 @ 文案与测试通知用例，移除 2 项随旧通道删除的用例）；构建后经控制面触发测试通知得到 `状态=sent、分段 1/1`，正文含 `@ 邮箱` 且随段携带 `atUids`；控制面设置页显示机器人应用与接收人，旧通道项已消失。

## workorder-agent：缺项提醒的接收人修正为「指派给」

- 背景：进一步澄清业务口径——工单由运营提单（提单人=运营），指派给设计师；字段由设计师在完成后手动补齐，因此提醒的对象是**指派给**而不是提单人。
- 处置：提醒文案改称呼**指派给**姓名，接收人改为该工单的**指派给邮箱**（`issues.assignee_email`，schema 升到 9）；快照复用策略同步改看指派给邮箱，使历史数据能补齐；Webhook 载荷的 `assigned_to.mail` 也一并采集；工单详情面板新增「指派给邮箱」。提单人邮箱保留用于展示与留痕。

## community 便携包：目标机开箱即用 + 补齐 Windows ARM64

- 背景：用户要求发行产物在任意干净 Windows 主机上直接可用——插件免二次安装、配置免二次配置，并补齐 ARM64 目标；打包机与目标机同架构。
- 处置：
  - 产物自带运行时：包内 Node 官方发行版（按打包架构下载并校验 SHA256）与内置 pnpm，目标机不需要预装任何运行时。
  - 离线依赖：仓库生产依赖与 profile 插件在打包时固化进包内 pnpm store，目标机首次启动离线安装，不访问 registry。
  - 免二次配置：profile、技能、全局 AGENTS.md 与非敏感设置随包携带；启动器强制使用包内家目录，不再被目标机已有的 `DSH_HOME` 顶掉。
  - 插件完整性：原本只靠开发 junction 存在的插件随包带入；registry 已下架的固定版本从本机已安装副本重打包，不擅自换版本。
  - 部署形态：排除插件源码与开发挂载脚本，并剥离 profile 补丁里的开发专用 HMR 行，避免部署包进入热替换与重建流程。
  - ARM64：运行时、store 与产物命名全部按架构参数化，在 ARM64 主机上跑同一命令即产出 arm64 包。
- 验证：x64 全链路实测——解压到干净目录、PATH 中无 node/pnpm，首次启动离线装好运行依赖与 297 项 profile 依赖，服务在备用端口启动并返回带令牌的 200 与 Web UI 启动标记；两个本地插件经共享回退目录解析成功。
