## 复核：开发者模式未能免除符号链接提权

- 现象：用户开启 Windows 开发者模式并重启后，非提权进程创建符号链接仍被拒（「此操作需要管理员权限」），在任何目录都不成立。
- 定位：注册表 `AppModelUnlock\AllowDevelopmentWithoutDevLicense` 已为 1、无组策略覆盖，但当前账户的管理员组身份是**经过 UAC 过滤的令牌**（`IsInRole(Administrator)` 为假），策略未对该令牌放行创建符号链接的权限。
- 结论：开发者模式在本机不是「重启即生效」的解法；收尾 profile 依赖图需在提权终端补跑一次安装，以 UAC 提示作为授权入口，不需要再次重启。
- 收尾（已闭环）：用户在管理员终端补跑 profile 安装成功（`Packages: +24 -12, added 24, done`），随后复跑安装返回 `Already up to date`，此前报 EPERM 的 `codex-shell` 链接目标已就位；记忆系统的 bundle 登记与运行时模块解析在安装后再次复检通过。此前的未完成状态仅为链接补齐，不涉及宿主代码，因此无需再次重启。

## 社区 dev 循环不再挂载已下线插件（codex-shell / git-timeline 反复出现的原因）

- 现象：两个已下线的自研插件在每次启动之后仍然出现在 profile 的组合包列表与 profile 的 `node_modules` 里，看起来从未下线。
- 定位：启动流程会在 web profile 启动时自动拉起社区 dev 循环脚本，而该脚本把插件工作区下的每个 bundle 插件都挂载进 profile 并把名字写回组合包列表——已下线的两个也在其中（源码按设计保留可回退）。于是形成「启动时播种删掉、启动过程中 dev 再写回」的拉锯；运行中的组合不受影响，它们并未被挂载，只是清单与 junction 看起来仍在。
- 处置：dev 循环改为读取同一份已下线清单，跳过其中的插件（不挂载、不登记、不开 watch），并在输出里说明跳过原因；同时清掉本机 profile 里遗留的两条组合包条目与两个 junction（源码目录未改动）。
- 验证：以已下线插件为过滤条件运行 dev 循环，只打印跳过说明并正常退出；主机自检不再报告这两个插件的漂移，只剩会在下次启动自动清理的宠物补丁行。
- 影响范围：`community/plugins/dev.mjs` 与本机 web profile 的清单、`node_modules` 链接；插件源码、profile 模板与运行中的实例未改动。
