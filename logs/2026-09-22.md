# 2026-09-22 开发日志

## 接入 Figma MCP（用户要求）

- 背景：用户要求把 Figma MCP 装进 DSH，并复用本机 Cursor / Codex 已装好的配置。
- 排查：两个客户端接的都是官方远程端点。Figma 的 MCP 目录只放行 VS Code / Cursor / Claude Code / Codex / Xcode，其授权服务器的动态客户端注册端点对目录外客户端返回 403；`dsh-mcp-client` 只支持静态请求头，不实现 OAuth 授权码与刷新流程。Cursor 一侧的 OAuth 令牌以 Electron safeStorage 加密存放，同样无法复用。结论是官方端点在本机接不进来。
- 选型：改用社区开源的 Framelink Figma MCP（15.8k stars、MIT、走 Figma REST API），不受白名单与席位限制；以纯配置组合包接入，不含 Host / Client 入口代码。
- 处置：新增 `community/plugins/packages/figma-mcp`，令牌从启动环境或本机令牌文件读取，不入库；组合包已安装进 desktop profile。令牌文件权限收紧为仅本人、SYSTEM 与 Administrators 可读写。
- 验证：服务器握手与工具清单通过；令牌解析在无令牌 / 仅文件 / 环境变量优先三种场景实测；真实调用 `mcp__figma__get_figma_data` 成功返回设计稿数据；热加载生效，未重启 Harness。
- 顺带修复：`~/.dsh/profiles/web/package.json` 携带 UTF-8 BOM，导致 `pnpm dsh` 在 seed 阶段解析失败；已去 BOM 并留备份，修复后 CLI 可正常引导。该 BOM 于 9/20 引入，与本次改动无关。
- 影响范围：`community/plugins/packages/figma-mcp/`、`community/plugins/README.md` 及中文版与配对记录、本机 desktop profile、本机 web profile 清单。

## 补上 Agent 画设计稿的能力（用户追问）

- 触发：用户问「为什么 Agent 不可以画设计稿」。
- 排查：Figma 的 REST API 只能读，写画布必须走 Plugin API；查官方工具表，MCP 的写工具（`use_figma`、`create_new_file`、`generate_figma_design`、`upload_assets`、`generate_diagram`）全部标注 Remote only，桌面版本地服务器只有读工具。官方两条路都提供不了写画布能力。
- 选型：加装 `figma-ui-mcp`（243 stars、MIT、当日仍在更新）。它是目前唯一能补上写画布能力的方案：插件在 Figma 内长轮询 `localhost:38451`，写操作经 Plugin API 落到画布，不需要令牌。星星数低于本仓 1000 的选库门槛，已在 PR 说明中显式记录。
- 处置：`dsh-figma-mcp` 组合包扩为两条通道（`figma` 只读、`figma-canvas` 读写），两者可用 `set_plugin` 独立启停；插件产物固定到 `~/.dsh/figma-ui-mcp-plugin`，与 npm 产物哈希一致；Figma 内导入插件属用户侧一次性操作。
- 验证：服务器握手与工具清单通过；重载后两台服务器均启动、桥接端口 38451 监听；实际调用 `mcp__figma-canvas__figma_status` 返回 `pluginConnected: false` 与插件未运行提示，确认工具已注册、只差 Figma 侧运行插件。
- 影响范围：`community/plugins/packages/figma-mcp/`（patch 与中文文档）、`community/plugins/README.md` 及中文版与配对记录、本机 desktop profile。
- 合并：经 PR #33 合入 `dev`。
